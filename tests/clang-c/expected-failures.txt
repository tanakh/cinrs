# The `clang/test/C` revisions whose answer `cinrs` does not match.
#
# One line per *revision* — one `// RUN:` line of one file — named
# `<dir>/<file>.c` when the file has a single RUN line and
# `<dir>/<file>.c:<n>` when it has more. Guard mode requires every
# revision not listed here to come out as the test asks; see
# `doc/clang-c-tests.md` for the outcome classes and the results.
#
# The corpus is not checked in: `scripts/fetch-testsuites.sh llvm` makes
# a sparse checkout of it, and without it the harness skips itself. This
# file therefore holds names and notes and nothing of LLVM's own.
#
# `!` here means `cinrs` refuses the revision on purpose and is right to
# — a Clang extension it declines rather than mistranslates. Guard mode
# asserts the refusal is still there.
#
# One id per line, with a note after it, and a marker in front of the
# id saying what kind of claim the line makes:
#
#   ID    `cinrs` gets this one wrong.
#   ?ID   It passes or fails depending on the toolchain, and is
#         guarded neither way.
#   !ID   This entry point makes the case invalid, so refusing it is
#         conforming behaviour and not a gap. Guard mode requires the
#         case to fail to *compile*; one that builds and runs is a
#         failure. The note may open with `error: "<substring>"`,
#         which the diagnostic then has to contain.
#
# Regenerate with
#
#     CINRS_CLANG_C_REPORT=1 CINRS_CLANG_C_UPDATE_EXPECTED=1 \
#         cargo test --test clang_c
#
# which keeps every `?` and `!` line as it stands.
