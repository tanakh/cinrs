# The `gcc.c-torture/execute` cases `cinrs` does not pass under `gnu11!`.
#
# Guard mode — the default, and what `cargo test` runs — skips these and
# requires every other selected case to pass. It also runs them, so that
# one which has started passing is reported and the line can go. See
# `doc/gcc-torture.md` for what the causes are, with counts.
#
# The corpus is not checked in: `scripts/fetch-testsuites.sh gcc` makes a
# sparse checkout of it, and without it the harness skips itself. This
# file therefore holds names and notes and nothing of GCC's own.
#
# One id per line: a marker, the id, a category tag and a note. A case
# that must fail and does fail is *correct*, so only a plain line
# records something wrong, and its tag says what kind of wrong:
#
#   ID  [bug]              `cinrs` is wrong here — it mistranslates
#                          the case, refuses code it means to support,
#                          or emits Rust that will not compile.
#   ID  [unimplemented]    A feature `cinrs` means to have and has not
#                          got to yet.
#   ID  [not-planned]      Deliberately unsupported, with a located
#                          error rather than a mistranslation. Nothing
#                          to fix.
#   ?ID                    It passes or fails depending on the
#                          toolchain, and is guarded neither way.
#   !ID                    This entry point makes the case invalid, so
#                          refusing it is conforming behaviour and not
#                          an error at all. Guard mode requires the
#                          case to fail to *compile*; one that builds
#                          and runs is a failure. The note may open
#                          with `error: "<substring>"`, which the
#                          diagnostic then has to contain.
#
# `doc/testsuites.md` is where the categories are explained. A failure
# that is not listed here at all counts as a bug until somebody says
# otherwise, and an update writes it in as one.
#
# Regenerate with
#
#     CINRS_GCC_TORTURE_REPORT=1 CINRS_GCC_TORTURE_UPDATE_EXPECTED=1 \
#         CINRS_GCC_TORTURE_STANDARD=gnu11 cargo test --test gcc_torture
#
# which keeps every `?` line, every `!` line and every tag as it
# stands. Deleting the file first re-measures the notes — and throws
# every tag away, so everything comes back as `[bug]  classify me:`.
