# The c-testsuite cases `cinrs` does not pass under `c89!`.
#
# Guard mode — the default, and what `cargo test` runs — skips these and
# requires every other selected case to pass. It also runs them, so that
# one which has started passing is reported and the line can go. See
# `doc/c-testsuite.md` for what the causes are.
#
# One test id per line, with a note after it, and a marker in front of
# the id saying what kind of claim the line makes:
#
#   NNNNN   `cinrs` gets this one wrong.
#   ?NNNNN  It passes or fails depending on the toolchain, and is
#           guarded neither way.
#   !NNNNN  This entry point makes the case invalid, so refusing it is
#           conforming behaviour and not a gap. Guard mode requires the
#           case to fail to *compile*; one that builds and runs is a
#           failure. The note may open with `error: "<substring>"`,
#           which the diagnostic then has to contain.
#
# Regenerate with
#
#     CINRS_CTESTSUITE_REPORT=1 CINRS_CTESTSUITE_UPDATE_EXPECTED=1 \
#         CINRS_CTESTSUITE_STANDARD=c89 cargo test --test c_testsuite
#
# which keeps every `?` and `!` line as it stands.
